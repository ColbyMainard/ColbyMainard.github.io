Beginner Guides to Data, AI, ML & Cybersecurity

Data engineering, software engineering, and artificial intelligence will stay in high demand for the foreseeable future as automation keeps expanding. However, many beginners may not know where to start and what to focus on. This page is that starting point: a sense of why each field matters, plus the tools to begin.

Data Engineering Guide

Last Updated: May 25, 2026

Cite this guide: https://colbymainard.github.io/assets/html/guides.html#dataEngineeringGuideDiv

Data engineering is the discipline of moving, shaping, and storing data so that downstream applications have consistent and stable datasets to work with.

The Importance of Clean Data

Real-world data often has missing or contradictory values, so you can't take the input for granted. Common issues can include:

  • Duplicate rows/columns
  • Extreme outliers
  • Irrelevant data
  • Inconsistent capitalization
  • Inconsistent data types
  • Inconsistent formatting
  • Columns contradicting each other
  • Inconsistent language (e.g. Chinese vs English)
  • Missing values (e.g. optional columns)

While exact policy will vary by project, I would recommend the following:

  • Deduplicate data in a consistent policy
  • Remove outliers
  • Remove unused data early and aggressively
  • Capitalize data using a consistent policy
  • Cast data to consistent types
  • Format all classes of the same type to the same format
  • Determine which columns are considered the source of truth in the event of a conflict
  • Each language might need its own preprocessing steps depending on character set and task
  • Impute value via either a default or estimate based on other columns

Handling User Data Responsibly

Many times, data being passed into algorithms can contain personally-identifiable information (PII). However, if this data is improperly handled, there are a myriad of potential consequences, like:

  • Loss of trust
  • Public relations nightmares
  • Legal consequences

I would recommend looking at the following to consider as a part of your pipeline:

  • Hashing sensitive fields to make it less readable
  • Salting sensitive fields to prevent frequency analysis
  • Least privileged access to data
  • Add cybersecurity checks to monitor and verify proper access
  • Check regulations regarding data being handled
  • Add k-anonymity and differential privacy to add noise for attackers

Data Velocity

The amount of data going through any particular pipeline over a unit of time will determine the robustness of infrastructure required. For example, text tends to have a lower overall processing and storage cost per sample than audio, with images/video being some of the most complex computing requirements. RAM, CPU, and GPU needs will largely be determined by the amount and types of data being handled regularly.

Batch vs Real-time

User needs will also impact the algorithm choices. When responses are required in real or near-real time, that caps how complex the processing can be and forces more compute to stay online continuously. If a user can wait for a response, however, it would make sense to either bundle requests together for efficiency or add additional processing power.

Common Libraries / Tools

  • Pandas for CSV exploration
  • Polars for high-speed tabular data processing
  • Spark for distributed high-speed tabular data processing
  • SQLAlchemy for handling interactions with SQL databases
  • BeautifulSoup4 for web crawling for data
  • Docker / Kubernetes for managing complex microservice architectures
  • python-dotenv for managing secrets

Computer Vision Guide

Last Updated: May 25, 2026

Cite this guide: https://colbymainard.github.io/assets/html/guides.html#computerVisionGuideDiv

Computer vision is particularly concerned with turning unstructured image data into a more structured analysis. Each pixel in an image is its own feature and contains little to no metadata and fuzzy decision boundaries (e.g. defining an exact edge).

Problem Classes

While many different problems can be solved via computer vision, it often boils down to one or more of the following categories:

  • Object classification
  • Instance Segmentation
  • Semantic Segmentation
  • Image classification
  • Pose estimation

Object Classification

Object classification can be used to draw bounding boxes around objects that the algorithm has been trained to find. This is best for finding regions of an image that might be interesting for further processing.

Instance Segmentation

Instance segmentation is similar to object classification but uses bounding polygons for more fidelity. This is best for determining which pixels belong to a particular object.

Semantic Segmentation

Semantic segmentation labels each pixel as a particular class but doesn't assign any pixel to a particular object. This is best when you need a class label for every pixel — say, separating road from sky — but don't need to tell two cars apart.

Image Classification

Image classification places the whole image into pre-defined categories. This is best for preprocessing of an image to determine if an image has properties of interest (e.g. contains dog, is a commercial).

Pose Estimation

Pose estimation is used for finding the position of a human's limbs in 2D/3D space. This is best for applications that need to know where particular parts of the body are in real space (e.g. movement tracking).

Choosing Models

I would recommend considering things like resource constraints, performance requirements, and infrastructure capacity to make decisions regarding models. As neural networks grow in size (e.g. number of weights/layers), they tend to gain performance to a degree at the cost of higher compute requirements and power consumption. Balancing these concerns will allow you to optimize the user experience.

Data Normalization Considerations

When building a computer vision pipeline, much thought needs to go into the data format expected. For example, many of the below are common concerns:

  • Number of channels (e.g. color vs grayscale)
  • Width and height of image in pixels
  • Rotation of training/test images for generality
  • Adding noise to train/test images for generality
  • Occlusion of portions of the image for generality

Common Libraries / Tools

  • Ultralytics for pre-built foundational models in many common tasks
  • PyTorch for building research networks
  • TensorFlow for building more performant networks
  • Keras for flexibility in swapping between PyTorch and TensorFlow
  • OpenCV for advanced programmatic image manipulation
  • Numpy for manipulating input and output

Generative AI Guide

Last Updated: June 17, 2026

Cite this guide: https://colbymainard.github.io/assets/html/guides.html#generativeAIGuideDiv

Generative artificial intelligence (GenAI) refers to various content (e.g. text, images, video) generated directly by a machine learning model. At the time of writing, the most well-known examples are Large Language Models (LLMs) like Anthropic's Claude or OpenAI's ChatGPT.

Underlying Tech

While the exact structure of the neural network will vary by application, it converts a specified input to novel data of a similar format. In the example of LLMs, input would be a text prompt and output would be a response to the text. Deepfakes, by contrast, would be audio/images/video of a specified person. Vision Language Models (VLMs) can handle both visual information and human language working in concert.

Generative Adversarial Networks (GANs)

These are the predecessor of modern GenAI. One of the most obvious differences was the introduction of the Transformer/MultiHeaded attention layers and the architectural flexibility it allows.

Common Libraries / Tools

  • HuggingFace's transformer package for pre-built foundational models in many common tasks
  • Ollama for deploying common production models
  • PyTorch for building research networks
  • CrewAI/Smolagents for building custom agents
  • TensorFlow for building more performant networks
  • Keras for flexibility in swapping between PyTorch and TensorFlow
  • Numpy for manipulating input and output

Natural Language Processing Guide

Last Updated: May 25, 2026

Cite this guide: https://colbymainard.github.io/assets/html/guides.html#nlpGuideDiv

Natural language processing (NLP) is the branch of artificial intelligence concerned with the analysis of human language.

Sentiment Analysis

Oftentimes, it is useful to be able to autonomously determine the sentiment someone holds about the topic they are speaking about. Neural networks of this flavor take in tokenized text and output a measurement of positive or negative sentiment (e.g. category labels).

Topic Detection

Deterministic algorithms tend to fail at detecting the true topic of a particular text. Some neural networks can bin texts into categories (e.g. tech, recent events, poetry).

Data Normalization Concerns

Neural networks are often sensitive to small perturbations in their inputs that humans may not be. When preparing to design and train a neural network for NLP purposes, it is often wise to consider the following:

  • How should data (e.g. letters/words) be tokenized?
  • What should the length of text be in tokens provided to the model?
  • Which languages are expected for the model to handle?
  • How should text with ambiguity (e.g. humor, sarcasm, riddles, contradictions) be handled?

Common Libraries / Tools

  • NLTK for natural language preprocessing
  • PyTorch for building research networks
  • CrewAI/Smolagents for building custom agents
  • TensorFlow for building more performant networks
  • Keras for flexibility in swapping between PyTorch and TensorFlow
  • Numpy for manipulating input and output

Reinforcement Learning Guide

Last Updated: May 25, 2026

Cite this guide: https://colbymainard.github.io/assets/html/guides.html#reinforcementLearningGuideDiv

Reinforcement learning (RL) is the branch of artificial intelligence concerned with learning optimal policies for behavior. Specifically, reinforcement learning optimizes a reward function in noisy, dynamic environments. Most techniques assume that there is an intelligent agent that takes actions in an environment and then measures its current state and the reward from the actions taken.

Techniques

Several reinforcement learning techniques are widely available for use. While the uses and exact math underpinning each are subtly different, the goal remains the same: determine the best action to take for any particular state. Some of the most popular techniques can include:

  • Proximal Policy Optimization
  • Q-Learning
  • Monte Carlo
  • Deep Q Network

Proximal Policy Optimization (PPO)

The basic strategy of PPO is to place an agent in an environment and let it randomly explore. After a while, the agent should have enough data to update policies based on which actions lead to particular rewards in an environment.

Q-Learning

If foreknowledge of the environment is available ahead of time and there are a finite number of actions in each state, it is possible to learn rewards for each action at each state. Based on that, it is possible to follow the optimal action at each state and estimate the future value of taking actions at any particular state.

Monte Carlo

This technique relies upon being placed in a certain state and being allowed to perform pseudorandom walks through the environment. After enough pseudorandom walks, it would be possible to estimate the expected present and future value of any action in a given state. Once there is some understanding of these expected values it would be possible for the agent to determine an optimal policy to maximize expected value in any situation.

Deep Q Network

When the environment is not known ahead of time, it is difficult to understand all of the variables that might impact a decision at any particular state in a robust way. Because of this, it becomes harder for developers to make sure all variables are directly built into the model appropriately. Neural networks can then be trained on the rewards earned by action/state combos and then be used to project the expected future value in these unknown environments.

Applications

This is generally considered its own paradigm of machine learning, distinct from supervised and unsupervised learning. In reinforcement learning, it is usually very clear to measure the quality of a solution objectively (e.g. high score in a video game). However, it might not always be obvious to humans the most optimal strategy or if higher scores are available beyond their current ability in an environment.

Software Engineering Guide

Last Updated: May 25, 2026

Cite this guide: https://colbymainard.github.io/assets/html/guides.html#softwareEngineeringGuideDiv

Software engineering has many definitions. For my purposes, I will define it as the process of designing software systems in a way to be both easy to maintain while remaining usable for the end user.

Why GenAI Can't Kill Software Engineering

Let's be honest: GenAI can write a sufficiently solid first draft of code to achieve known features. However, this is rarely the issue for most large projects. GenAI tends to struggle in many complex tasks, like:

  • Understanding personal taste of the end users
  • Intuition regarding human needs
  • Surfacing hidden requirements the user never actually specified
  • Designing user interfaces that humans consider easy-to-use
  • Understanding unstated priorities that users may have

Practical Concerns

"Always code as if the guy who ends up maintaining your code will be a violent psychopath who knows where you live." - John Woods

Eventually, every line of code in a repo will need to be updated or otherwise replaced once no longer needed. These requests for the edits can frequently come after the original author has retired, died, or otherwise left the organization maintaining the code. Because of this, it is best practice to design the code along principles that make hand-off of responsibility easier. I would recommend Clean Code: A Handbook of Agile Software Craftsmanship for the low-level code standards. However, this is often not enough for substantially new projects. To design systems from the ground-up responsibly, I would recommend Design Patterns: Elements of Reusable Object-Oriented Software.

There are several directions you could go after this. For resources to learn programming languages, I would recommend either my list of Python or C++ resources. Others may find my scripting or operating-systems resource lists useful.

Cybersecurity Guide

Last Updated: May 25, 2026

Cite this guide: https://colbymainard.github.io/assets/html/guides.html#cybersecurityGuideDiv

Cybersecurity is the practice of hardening computer systems and those who use them against malicious individuals. This could look like securing computer networks, patching hardware and software vulnerabilities, or social engineering training.

Best Practices

Non-technical users may feel like there is nothing that can be done. While they may not have the tools to find zero-day vulnerabilities, there are several practices that can give them some security.

  • Update programs and operating systems regularly to get security patches
  • Use penetration tests or similar when possible
  • Enable multi-factor authentication for online accounts where possible
  • Use strong passwords that are unique to an individual site
  • Consider password managers like 1Password to help keep track of credentials digitally
  • Install applications from trusted sources only
  • Delete unused applications and online accounts to minimize your digital footprint
  • Make answers to security questions something that doesn't line up with what would be available online (e.g. wrong answers only)
  • Do not post about being at an event until after you have returned from the event
  • Ignore all scam emails and delete immediately - they may contain malware

Fields in Cybersecurity

Many think that cybersecurity is a monolithic topic, but there are many distinct subfields, including:

  • Network Security
  • Application Security
  • Digital Forensics
  • Cloud Security
  • Ethical Hacking
  • Governance, Risk, and Compliance (GRC)

Network Security

Network security is primarily concerned with making it difficult for those with malicious intent to gain and escalate access to computer networks. Many attacks come over wireless networks at some level, and catching/blocking these issues early is the best way to avoid a sizable cybersecurity event.

Application Security

Each application needs to make sure it safeguards users without them consciously thinking about it. Application security does this by securing the whole software development life cycle. By doing so, it removes bugs that malicious actors could use to attack users as soon as possible.

Digital Forensics

Understanding the state of a computer can be useful in both file recovery and criminal cases with a digital component. However, cyber attackers often go to great lengths to hide their malware from security. Digital forensics builds the tools and processes that are needed to analyze both the digital artifacts and behaviors that were seen before a system was damaged and restore as much as possible.

Cloud Security

Many companies have their digital operations at least partly in the cloud. Many safeguards that are easy for machines within physical reach are harder to apply in the cloud. Cloud security focuses on responsibly configuring cloud environments to protect resources.

Ethical Hacking

Most have some level of cybersecurity practices to mitigate the risks and likelihood of cyberattacks. Cyber attackers, however, usually go out of their way to hide their activity until they have completely dismantled your defenses. This makes it difficult for someone who developed the defenses to understand concerns they may have overlooked. Ethical hacking, or penetration testing, focuses on hiring talented individuals to attempt to defeat the defenses and report back with relative strengths and weaknesses. Once these strengths and weaknesses are known, it is possible to then improve a cybersecurity stance in a logical and impartial way.

Governance, Risk, and Compliance (GRC)

It is impossible to design defenses if it is not established how data and systems should be protected. GRC focuses on establishing protocols on how confidentiality, integrity, and availability should be guaranteed at a system level.

  • Scapy - working with network packet captures
  • Metasploit - penetration testing for known vulnerabilities
  • Scrapy - web scraping
  • BeautifulSoup - alternate web scraping
  • Nmap - Exploring what devices are available within a particular IP range
  • Hashcat - Breaking cryptographic hashes
  • John the Ripper - Password Cracking
  • Netcat - Reading and writing network data
  • Aircrack-ng - Testing security of various WiFi networks
  • APKTool - Looking for vulnerabilities in APK files
  • SQLMap - Looking for SQL injection vulnerabilities
  • DirB - brute forcing URLs on web servers
  • Reaver - Looking for WPS Vulnerabilities
  • XSStrike - Finding and exploiting cross-site scripting (XSS)
  • Nikto - Web server scanning
  • Autopsy - Data recovery and file system analysis
  • Maltego - Freemium open-source intelligence (OSINT) searches
  • Burpsuite - Freemium penetration testing suite
  • Wireshark - Recording and exploring network packet captures
  • Social Engineering Toolkit - Building out social engineering campaigns for penetration testing
