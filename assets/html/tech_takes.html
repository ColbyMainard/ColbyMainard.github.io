LLMs: good for natural language processing, but nothing else

Last Updated: October 3, 2025

“The question of whether a computer can think is no more interesting than the question of whether a submarine can swim.” - Edsger Dijkstra

The Good

Autocompletion of Work

LLMs tend to see lower errors in environments where the prompt is succinct, does not require long-term strategic thinking, and relevant documentation was provided by processes like retrieval-augmented generation (RAG). If a human provides a very clear structure for the LLM, limits the scope of the ask, and provides all necessary context, the LLM can make a good first pass at what it believes should be the next words.

Summary of Documents

When provided with documents containing the required information in a succinct enough method that fits into the memory of the LLMs, LLMs can read and provide decent summaries of document contents and answer basic questions. For reasons discussed later, no LLM can fully replace humans for more advanced reading comprehension. Agentic workflows have mitigated this problem somewhat by recursively breaking problems into more manageable pieces. However, as each component of an agentic workflow also contains calls to LLMs, it does not fully solve what would happen if input overwhelms any individual step. This worst-case scenario simply trades the likelihood of failure at any particular step with more potential points for failure.

Polishing Writing

Many LLMs can be passed a document, with some able to process images, video and diagrams in addition to the text processing available in initial releases. Once the context of the document is parsed, LLMs could be used to suggest edits to documents that would improve vocabulary choice, tone, clarity, and many other facets of writing. In its current state, AI cannot fully replace humans when creating the initial drafts of documents. All AI techniques for generating text require some sort of initial input. This initial input is usually a combination of the initial training data and user-defined input.

Improved automation for NLP-related tasks

Before LLMs, there was no good way to interact with computers using predominantly natural language. Natural language processing (NLP) was a very difficult field, and most NLP systems were given a very narrow scope to help address very specific questions that the end user might have. But the easiest method for processing language data would be to store it within a database and have end users query that database in a very rigid format (e.g. SQL for relational databases containing raw text and metadata). In contrast, many users yearn for a user interface similar to that in Star Trek, where the user can have a full conversation with the computer to achieve whatever they desire without worrying about technical implementation. LLMs were the first taste that many users had to this interface (assuming that programming/query description languages don't count). I think it fair to label LLMs as one of the first viable prototypes of this interface. While there is no shortage of potential pitfalls that still need to be addressed, it is a clear step in that direction.

The Bad

Over-reliance

No AI model can think for you.

Regardless of machine learning technique used, the underlying model is utilizing a set of mathematical equations and a set of learned parameters / boundaries that were extrapolated from the training data was available. While that training data may be more data than a human could process in a million lifetimes, that does not mean that it is safe to outsource the thinking to any of the existing AI and related technologies.

All of the available tools in AI are focused on one thing: make a best guess at underlying patterns that are supported by the dataset available. There is no common sense module within an LLM. LLMs do not possess the ability to think, understand, believe, fear, love, hate, trust, doubt, or any other action that makes them feel particularly human. Humans are much better at anthropomorphizing inanimate objects than inanimate objects are at mimicking the abilities of sentience and self-awareness. It is best to keep that in mind before assigning them tasks that require the accountability that would normally be associated with sentience. Autonomy and accountability are two sides of the same coin: any system we cannot hold to account for its actions should not be given the autonomy to cause unmitigated harm.

Hallucinations

As LLMs in particular and ML models in general do not have an inherent understanding of the world outside of the computer, hallucinations are an inevitability. Since the model doesn't have components that allow it to do a lot of features that allow humans and animals to determine the validity of presented information, there is very little the model can do to determine the truth of statements outside of what has been provide within datasets used to train.

Limited working memory

All LLMs operate on tokens. What exactly constitutes a token depends on the implementation of the LLM and tokenizer you are using, but it is probably simplest to think of it in terms of words. There is only so many tokens that a program (in this case, the LLM would be a component of the program) can handle. Because of that, LLMs must choose between expiring older data or run out of RAM and crash. This problem can be mitigated with RAG, but a lot of models have built-in recency biases that may require reloading of documents used from previous queries.

Unexamined biases

"All models are wrong, but some are useful" - George Box

There are two factors that cap the potential real-world usefulness of an AI model: the training data it was given, and the number of learnable parameters the model has to get as close as possible to the training data. It should not surprise anyone that one of the easiest ways to bias a model towards a particular output would be to give it training data that supports such a bias. Since there are no moral guidelines inherent to the LLM itself, it would be possible to get the model to output content that would be decried for a medley of reasons. It would be possible to generate content that would be considered racist, sexist, homophobic, xenophobic, antisemitic, or any other content that would probably have a legal/public relations team working overtime. There has also been so many AI deployments with legal ramifications that there are already articles showcasing lists of the worst offenders. As such, it is best to examine every step of your AI pipeline for potential security risks and the ramifications for those risks.

Cybersecurity concerns

"The only truly secure system is one that is powered off, cast in a block of concrete and sealed in a lead-lined room with armed guards - and even then I have my doubts." - A. K. Dewdney, March 1989

While the original author may not have foreseen all of the implications of of this quote as it relates to the security of LLMs, the sentiment is still well-paced. Over the past few years, we have seen a plethora of incidents that should raise concerns about how companies are implementing security controls, including:

  • Exposed DeepSeek database leaks sensitive data
  • 10% of employees of GenAI prompts include sensitive data
  • Anthropic confirms that it suffered a data leak
  • OpenAI confirms ChatGPT leaks sensitive user data and suspects hack
  • Samsung bans ChatGPT and other LLMs after code leak
  • ChatGPT leaks data after simply being asked to repeat a word endlessly
  • RAG used in ConfusedPilot attack to reveal enterprise secrets
  • 12000+ API keys found in LLM training data
  • FBI sends out public service announcement regarding AI-powered phishing and related scams
  • AI is generating malware, and other scams
  • Deepfakes and other AI-powered Cyber Attacks

Clearly, with this volume of potential security issues, it is important to have multiple levels of security to prevent attacks against data that should never be exposed to the internet. Asking the chat bots to please not leak data is going to be insufficient for even the most basic applications. This will be especially true for applications that deal with financial, medical, and other confidential data that already have data protections in most jurisdictions. As with any technology, the best security posture would be to have a multifaceted and layered approach that does not have any single point of failure. Similar approaches make it more difficult for attacks to damage core functionality, even if they discover a legitimate exploit.


App Stores are hurting the web

Last Updated: October 7, 2025

Why

Monopoly over user base

Certain tech platforms, most notably Apple, have been receiving pressure to take down walled garden ecosystems. The crux of the issue is that users are not able to swap platforms without considerable friction. While some level of friction will always exist, the problem is that platforms are adding friction solely to discourage users to swap to other platforms. Examples would include blocking apps that would make it easier to move data to competition, diminishing usability of 3rd party smartwatches, and limiting 3rd party digital wallet.

Many apps don't need to exist

It is my opinion that apps should be designed to add functionality that was not available as a part of the device as originally purchased. However, many apps are thinly-veiled web clients. Because of this, many applications could be bypassed with a web browser that is already available for most consumer and enterprise devices. By encouraging users to download applications to access what should be just be a single website, this wastes resources on both the device and the developer. The device has less storage, and the developer now has to support both the app AND the website.

What users can do about it

Bypass app stores where possible

Many app stores take a substantial cut of any purchases made in-app. Both Google and Apple, for example, have been known to take 30% of in-app purchases. By not using app stores, you cut out the middle man and reduce the profit of app stores. Developers could then offer the same usability for cheaper with better profit margins and less stress, while consumers have more space on their devices. While this might be difficult for non-technical users initially, these businesses respond to profits at the end of the day. Reducing their profits due to anti-consumer practices would encourage leadership at companies to reconsider their business strategy and align it to end users.

Support of anti-monopoly action

Sometimes, there isn't a good option available for consumers to opt-out of using app stores and go directly to developers. After all, app stores have incentives to keep apps on the app store to continue charging fees as middle men. While some fees are required to maintain the app store, there is also a perverse incentive to push consumers to use apps through the default app store on the device and wasting resources on the consumer device. As such, I would recommend reaching out to the Electronic Frontier Foundation, as they are already taking steps to pressure legislators to take action against monopolistic tech practices.


Not everything needs to be a subscription

Last Updated: September 24, 2025

Subscriptions are a very tantalizing business model where it makes sense. However, forcing it where it is neither needed or wanted will cost a lot of good will from consumers.

Users are getting subscription fatigue and rebelling against those who insist we will own nothing and be happy. It is my opinion that many companies have chased adding subscriptions where they don't belong in an effort to chase recurring revenue and boost valuations. Adding unnecessary friction only to allow users to bypass it by opening their wallet is liable to produce backlash, like how BMW was bullied out of their heated seat subscriptions. However, some business models make sense for it to be a subscription. Because of this, it makes sense to differentiate between when a subscription makes sense from where it will simply cause frustration.

Legitimate uses for subscriptions

  • Indefinite/infinite support/work for product expected after acquiring user.
    • It is not economically viable to promise infinite resources in exchange for an up
    • User requests for ongoing support and labor from the company, resulting in additional cost.
    • Billing clients for continuous service requirements often require periodic billing.
  • User to make ongoing requests for resources.
    • Similar to the last point.
    • When continuous service is built into the business model, it doesn't make sense to offer it for free.
  • Any environment in which it makes sense to charge predominantly by resource usage.
    • Fixed cost per request.

Where subscriptions are going wrong

  • Locking down hardware users already purchased, only to unlock for additional fee.
    • HP bricking printers not enrolled in ink subscription
    • Adobe vs FTC: hard to cancel annual membership.
    • Up to 76% of websites use shady practices to get users to subscribe
  • Users loosing access to Software-as-a-Service (SaaS) with little or no notice

The internet should not require ID

Last Updated: October 7, 2025

"Those who would give up essential Liberty, to purchase a little temporary Safety, deserve neither Liberty nor Safety." - Benjamin Franklin

Why has privacy disappeared?

Privacy matters to the individual to preserve many of their other rights. It is so fundamental that measures guaranteeing certain levels of privacy were enshrined in the US Constitution as a response to various attempts at government overreach, including overreaches that lead to the Revolutionary War that lead to the formation of the country in the first place. Examples of these protections would include:

  • Protections against unreasonable search and seizure.
  • Protections guaranteeing right to disseminate information freely.
  • Protections to associate with others freely.
  • Protections in regards to self-determination of religion.
  • Rights by default belong to citizens.

Companies found digital gold

Many companies do not have the same stringent requirements that governments have in regards to respecting privacy (depending on jurisdiction). While there are certain limitations based on industry and the contents of certain personally-identifiable information (PII), as long as the end user willingly gives the company their data, the company can do whatever processing they want behind the scenes. This processing could include things like building advertising profiles and other data mining features that can be sold to companies to better understand individual behaviors. Selling user tracking data has become so common that companies like DeleteMe and Incogni offer services that aim to reduce the ability for companies to track you.

Governments want control

By purchasing data from companies, governments can potentially sidestep unreasonable search and seizure. Since the data was willingly provided to the company and the company willingly provided the data to the government, the government can legitimately claim that they did not take your PII without your consent. Some governments are looking for access to more fine-grain data of what citizens of their country are doing online and influence their browsing choices without making it obvious that they are doing so. Governments wanting to do so could try to force users accessing the internet to provide government IDs to access either the internet itself or when accessing content the government would like to restrict. While this sounds theoretical, the UK has run into some controversy from implementing new restrictions trying to ban children from accessing certain content. Despite this, several US states have been attempting to implement similar laws. Some of the content being regulated is admittedly unsavory. My argument, however, focuses on the dangerous precedents being set by the poorly-written legal language. There is nothing preventing authoritarian/totalitarian regimes attempting to manipulate their country's internet browsing behavior using similar technologies and laws. Even worse, these laws don't exist in a vacuum, and will be impacted by:

  • VPNs circumventing local regulations
    • Regulations are only enforceable within geographic boundaries.
    • Easiest way to handle this is to check IP address and using that to approximate location.
    • VPNs redirect web traffic to a third party location that may be outside the regulated area.
  • Legitimate users put at higher risk
    • If the regulation actually achieves its goal, all accounts could be easily traced back to a government ID.
    • Tracking users across sites could be trivially easy.
    • Could allow hackers to damage many lives by doxxing legitimate users.
  • Concerns around unreasonable search and seizure
    • Assuming no laws are being broken, why are governments so invested in attaching an ID to web traffic?
    • It is unclear how the data is handled on the backend.
      • How long is the data stored?
      • How is this data protected?
      • Who/what has permission to access the data?
      • Does this regulation actively weaken protections from other laws?
      • How is data processed?
      • What safety measures are in place if something is processed incorrectly?
  • Users lie all the time
    • What if someone has a high-quality fake ID?
    • Can someone else's ID be used?
    • In the case of account takeover, would the original account holder be liable for the stolen account?
    • How should things be handled when traveling between regions not requiring ID information and regions that do?

What can you do about it?

Avoid logging into sites where possible

The quickest and easiest way to de-anonymize yourself in online spaces is NOT logging into websites. By signing into websites, you are actively handing data to the site you are logging into. It is worth noting there are other techniques to de-anonymize your online behavior. That being said, why make the role of a data broker easier and more cost-effective?

Using privacy-preserving browsers

TOR and Brave offers additional tools to help keep users of anonymous, like hiding IP, blocking cookies, and making it easier to prevent tracking with JavaScript. TOR has much more tools turned on by default, but tends to be slower due to the technique used to hide the IP address. Either way, for those worried about internet privacy, these browsers are known to be well and truly above the rest.

Pressure legislators who sacrifice privacy for "safety"

Many legislators have not thought through the potential identity verification to access certain content. However, there are already known hacks that demonstrate the potential issues around sites doxxing the government IDs of users. For example, the Tea app may have allowed hackers to access up to 72,000 government IDs of users. The stated goal of the site, to call out abusers to prevent domestic violence in dating, is noble. De-anonymizing users could actually increase domestic abuse in this case, as abusers could use this hack to tie posts back to the government ID of the associated account. It does not take too much imagination to see this style of hack negatively impacting similarly vulnerable populations.

For those worried about the potential misuse of ID data, I would recommend reaching out to the Electronic Frontier Foundation for tools and resources in pushing for intelligent policies. Kolmogorov-Arnold Networks (KANs)

Last Updated: October 7, 2025

What are they?

Kolmogorov-Arnold Networks are an interesting alternative to the current neural network technology based on multi-layer perceptrons (MLPs). The internal structure of traditional neural networks are perceptrons organized into layers. Each perceptron takes a set of inputs as numbers as a matrix, performing a linear transformation (e.g. matrix multiplication), and outputting a numerical value. Predetermined activation functions (e.g. sigmoid and rectified linear unit) are then applied to outputs of each perceptron and passed from layer to layer until the neural network has arrived at an answer. In this structure, it is common to have many different perceptrons, each solving a miniscule portion of the problem. KANs, on the other hand, are interesting because they do not rely on predetermined activation function. Each perceptron in a KAN is responsible for learning its own activation function with splines. Because of this, each perceptron is much more robust than comparable MLPs. This additional robustness allows KANs to use fewer perceptrons to achieve similar performance.

Pros

Improved interpretability

Thanks to each node of the KAN learning it's own spline, this would allow users to visualize how a change of input impacts the output of that node. Once a user understands each node as well as how data flows through the network, it would be possible to visualize how changing an input would change outputs. When comparing this to MLPs, it is much more difficult to determine how weights and activation functions have meaning in a larger context. Not only are there arbitrarily many perceptrons in current neural network architectures, many of these perceptrons interact with each other by virtue of this architecture. Because of this, it is almost impossible to generate a visualization that both generalizes the patterns that the MLPs discovered and is easily comprehended by the human mind. KANs, by comparison, have very few units composing it. This makes the combinatorial amount of visualizations are easier to merge together to make an interpretable model that is much more approachable for the average human.

Accuracy

Because each node of the KAN learns it's own activation function in addition to learning weights, each node can more accurately fit a component of the problem. Since activation functions are typically defined by the user for MLPs, there is no guarantee that the function chosen by the user is the best possible. Even when taking into account the use of hyperparameter tuning, this tends to yield only the best activation function of those tested. The exclusion of poor activation functions does not exhaustively that the best activation function was chosen to fit the data to the exclusion of all others.

Cons

Less developer support

As the paper I was able to find for this demo was only released in 2024, most AI developers haven't had much time to play with this relatively new technology. The fact that LLMs have consumed so much of attention from non-technical users has redirected the efforts and limited time that developers have to keep up-to-date on current technologies. When developers are limited in capacity, they inevitably focus on the features that stakeholders like users and business leaders demand. Despite the fact that some technologies in the proof-of-concept phase could perform better than widely-available technologies, developers need to be both aware of new technology and have the resources to integrate it. Combining the novelty of KANs and the extremely fast, chaotic impact of AI on business strategies has lead to a lack of resources to explore how KANs could change the game fundamentally.

Parallel Processing / Speed

There are several features that have limited the max speed of KANs, like:

  • More complex logic
    • Internal logic learns both activation function and weights/biases.
    • Harder to cache and make operation possible to run in a batch.
    • Developments that would allow KANs to take advantage of hardware like single instruction multiple data (SIMD) and graphics processing units (GPU) not implemented yet.
  • Integration with MLPs
    • Certain tasks may make more sense to leave implemented in MLPs, as performance is more of a known quantity.
    • Libraries designed to make this manageable for the average don't exist at the time of writing.
  • Saving and sharing KAN models with others
    • No standard interchange format currently exists (to my knowledge).
    • Interchange and save formats would need to not interfere with optimizations to make KAN speed comparable to MLPs.

What are cryptocurrencies?

Pros and Cons of Investing in Crypto

To establish what the cryptocurrency market, I will compare and contrast it with more traditional securities. Traditional securities include things like stocks and exchange-traded funds (ETFs).

Category Traditional Securities Cryptocurrency
Asset types This usually represents partial ownership of companies or other assets. Cryptocurrency is protected by securing a decentralized database known as a blockchain. However, it is important to understand that many cryptocurrencies do not have any underlying assets setting value.
Regulation Traditional securities are very heavily regulated and often have very strict financial reporting requirements. Violating these laws can lead to various fines and jail time for those who knowingly violate these regulations. While cryptocurrencies have been receiving some government attention and regulation, they are still much less regulated. Similarly, it is much easier to perform unsavory activity.
Volatility As there is an underlying asset, prices of this security will be related to the underlying value of the asset and sentiment of future performance. The underlying assets serve as a base that reduces the variability. Cryptocurrencies are generally not backed by assets. Therefore, any variability can be tracked back to differences in supply/demand and sentiment.
Intended Purpose This is usually used to transfer ownership of publicly-traded entities. Due to this, it is a good way for publicly traded companies to raise capitals and for investors to gain access to partial business ownership. Cryptocurrencies are usually designed as a digital-only currency. It would be the equivalent of a volatile currency exchange between fiat currencies and their crypto counterparts.

    Future of Quantum Computing

    Last Updated: October 18, 2025

    What is quantum computing?

    Quantum computing is using various principles of quantum mechanics to perform useful calculations. The base unit of these computers is the qubit. Qubits, like traditional bits, are able to take on values. Traditional bits have no uncertainty and always take the value of either true or false, while Qubits can have uncertainty by taking a state that is a combination between true and false.

    Where is quantum computing most useful?

    Because of the fundamental difference in how the underlying hardware handles uncertainty, algorithms can be written to take advantage of this. Uncertainty collapses upon reading the state of the qubits, and this collapse propagates through the circuit by virtue of how quantum physics behaves. Digital computers don't have this advantage, and software/hardware engineers need to explicitly need to propagate bit state changes. Allowing physics to much of the heavy lifting, it is possible to perform operations much faster with sufficient hardware. While quantum computing isn't mature enough to be general hardware, it has potential to speed up certain domains, like well-known NP problems. These problems tend to grow exponentially or worse on digital hardware. Quantum, however, grows its computing power exponentially with the number of qubits the quantum computer has.

    Where will quantum computing likely go?

    Quantum computing is still in its infancy. Because of that, all guesses are where it will take computing is speculation at best. However, there are potential parallels with the Graphics Processing Unit (GPU), Tensor Processing Unit (TPU), and other Application Specific Integrated Circuits (ASICs). All of these are good at improving performance for certain classes of problems, but the inverse is true if the problem is converted to this form poorly. GPUs are good with processes that can be broken into many smaller problems with relatively simple logic. TPUs are best for matrix-specific applications. ASICs are usually custom built for specific tasks, with GPUs and TPUs being possible examples of the most popular. It is likely that quantum computing will start as a hardware accelerator only really affordable for enterprise and government applications. Later, it is possible that quantum computing will become affordable to access for individuals, but several engineering challenges will need to be overcome first. The main issues are going to be in prohibitive energy costs, cooling, and having enough qubits available to actually be functionally useful for consumer applications.
